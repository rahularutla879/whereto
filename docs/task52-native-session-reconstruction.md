## Implementation and transitions

`native_graph.py` uses a fixed reviewed backend model registry and six named native factories, exact field whitelists, typed validators, bounded references/sets/tuple keys and alias preservation. No pickle, arbitrary import path or executable deserialization. Unknown fields/classes, cycles, nonfinite values, mismatched resolver ownership and corrupt advanced candidate history refuse. Internal non-JSON keys are represented as typed graph data, not stringified ambiguously. Current limits:512KiB canonical plaintext,20,000 nodes,64 nesting levels; encrypted compressed records must also fit the unchanged64KiB Redis record limit and350-record/128MiB namespace limits. Compression is bounded on both write and decompression. Real Google content is **not admitted** by this synthetic codec: the existing [field-level privacy review](task52-shared-evidence-privacy-v1.json), provider terms and hosted retention approval remain gates, including page-token/route/result fields now represented locally.

`native_sessions.py` composes the frozen grant/evidence/bridge algorithms. A server-owned `Ticket` identifies a checkpoint/revision; no HTTP route, browser-selected raw graph, environment enablement flag or startup selector is added. `Session.capture` binds an existing validated source and its protected original inference/root/outing. `Session.resume` verifies parent/new source manifests, current SQL/epoch, complete witness prefix, fence, encrypted anchor/hash/AAD, current revision, fixed build, freshness and native validation before returning a usable object. A worker claiming the checkpoint fences the prior worker. The replacement broker adopts the recorded reference clock, even when its server factory initially supplies a different one. Original source edits revoke the checkpoint and require a separately validated source; they do not copy its graph or silently make a model call.

A continuation commits `native_begin` before invoking the actual broker method (`answer`, `plan`, `advance`, `more`, `contact`). Success captures the changed native state at a new revision, preserves the minimum original deadline, encrypts with Redis CAS and installs an issuer-only SQL commitment. Failure or process death leaves the revision BUSY: no automatic repeat, inference, discovery or refund. This is deliberately conservative, including failures before provider I/O; automatic interrupted-turn recovery is not implemented. A recoverable application error uses the existing expired/provider error vocabulary and asks for a new validated search rather than reconstructing missing state.

Additive `native_sessions.sql` protects immutable checkpoint/turn/commit/action links and replaces only the **synthetic** worker front door. Old unfenced revise/revoke calls cannot mutate native checkpoints; leased transitions require the current worker/fence. Linked financial operations recheck that checkpoint and its committed evidence. Runtime has no direct table mutation or execution of issuer-only commit/enrollment/action routines. Bootstrap/issuer remain privileged, separately authenticated synthetic roles. The unchanged parent SQL files, source pins and financial algorithms are not rewritten.

Candidate/history progress is security-relevant even when no provider cost occurs. `native_witness.sql` mirrors each new checkpoint commitment as a zero-charge immutable witness fact; the existing financial comparison then detects restored older nonfinancial history as well as restored financial reservations. Publication is **not** an atomic Redis+two-SQL transaction: a torn CAS/anchor/witness/commit sequence fails closed, and reconciliation is an operator requirement. A new checkpoint fact cannot reset counters or release money. All actual fake dispatch continues through current action, admission, decrypted evidence, protected reservation, exact canonical payload and single-use delivery checks. A reconstructed session alone cannot dispatch.

## Versioning, failures and unsupported paths

The new source manifest binds this implementation and tests to the unchanged parent cohort. It is a separately named build, not an exact historical environment reconstruction or a V4/V5.1 evaluation approval. Records require the **exact** build; unknown/new/older builds refuse. Upgrades must either retain an explicitly compatible reviewed server cohort until its original sessions expire, or deliberately invalidate sessions. No automatic cross-version data migration exists. Deployment/software rollback must preserve SQL and witness financial/replay history; restoring old records is not a budget reset.

Supported local paths include recorded pending-date completion, ordinary planning/options/Details, advanced resolver/router/history including authored optional/flexible/return cases, reusable selected receipt selection, and purpose-specific saved refresh with fresh access checks. The tests use actual planners and typed contracts, not a second planner. They do not bypass the existing legacy optional-coffee ordering loss or activate V5.1. Individual missing-date/area/origin/duration clarification behavior remains governed by existing native contracts; this checkpoint does not certify every combination through browser HTTP workflows.

Remaining unsupported paths: exploration's live `DevelopmentCost` ledger; active/in-flight callbacks/operations; standalone pre-source origin suggestions; full source-independent1800s Details continuation; arbitrary extension objects; automatic repair of torn or BUSY turns; cross-version migration; fresh inference after changed meaning; recovery of missing route evidence; actual persistence/RLS writes or hosted session routing. A trusted internal routing/index service and separate workload-authenticated factories/issuer/counter/dispatcher are still required before normal endpoints can use these tickets. No public API or saved DTO change was made.
