## Autoscaling, bounds and operational controls

Cloud Run scales by CPU/concurrent requests; use measured request slots/CPU, not only low CPU while all workers block on providers. Set explicit thread capacity and nonblocking admission; process-bound locks cannot be the production authority. Start 8 in-flight work slots/container with no more than approved fleet model/provider leases; separate saved/read actions so a model flood cannot consume all database/read capacity. Avoid multiplying a4-connection semaphore by an unbounded replica count. Maximum replica setting includes temporary rollout overshoot in connection planning; shared admission is the actual provider ceiling.

Initial worker budget proposals:250ms shared admission;5s target total, with a longer clearly reported hard stop (e.g.15s initial planning) to avoid discarding valid work at 5s merely for statistics. Exact AI/search/route socket budgets are chosen from staging measurements, nested inside remaining total deadline. On deadline/cancellation prevent next dispatch, retain unknown send reservations; propagate AbortSignal/client disconnect as current code does. A5s SLO is not a transport timeout contract and cannot be achieved by failing all slow requests at 5s.

Fleet capacity can rise only when all dependencies pass: model RPM/TPM/latency, Google methodQPM/MatrixEPM/daily quotas, SQL locks/connections, Redis bytes/ops, CPU/thread capacity and monthly budget. Check 80% sustained usage/rejections before scaling; no automated Google quota increase. Inference reservations/latency circuit breaker stop new dispatch on provider outage, no unapproved retry/failover vendor.
