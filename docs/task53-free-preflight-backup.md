## B1 — encrypted off-site logical backup, separately gated

Use 0700 working directory / 0600 encrypted outputs, exclusive creation, no symlinks, no plaintext dumps/logs; stream directly into authenticated encryption. Incomplete pipelines or any source/export warning fail closed and are not published as a successful backup.

Review-only export argv (not executable authorization; credentials supplied by the established protected operator mechanism, never a URL/argument):

```

```

Stream each output through the owner-approved recipient encryptor; use pipefail and a bounded supervisor. Preserve ownership/grants/RLS/triggers/functions/schema/data/sequence values and database ACL/settings; do not add no-owner/no-acl/disable-triggers flags. Globals/role metadata must include relevant custom roles/memberships/attributes without password hashes; preserved LOGIN roles require separately authorized credential re-enrollment after a restore. Never use an RLS-limited dump that silently omits rows. Permission errors or required managed-object omissions are blockers, not ignorable warnings. Archive a coverage manifest for all schemas and platform exclusions, source/client versions, timestamps, encryption recipient fingerprint, ciphertext hashes and before/after catalog/data baselines. No full dump or user rows belong in Git.

**Timing gate:** upstream [pg_dump17 source](https://raw.githubusercontent.com/postgres/postgres/REL_17_STABLE/src/bin/pg_dump/pg_dump.c) resets its own statement/lock/idle/transaction timeouts; the lock-wait option applies to its initial table-lock phase. PGOPTIONS cannot enforce a 1500 ms dump query deadline. Therefore B1 is **not enrolled** until the owner separately approves a finite **backup-operator-only timing scope** (proposed total 60 seconds, no automatic retry, 250 ms initial lock wait) or a separately verified stricter export mechanism. No application/witness deadline, SQL routine, role default, grant or reservation is altered. If no exception is approved, keep live export refused; do not silently run an unbounded dump.

A single pg_dump has a consistent database snapshot, but role metadata, sequence state and separate baselines are not magically one atomic snapshot. Use the approved quiet window, compare before/after baselines and reject drift. A future capture must include any operational financial history that actually exists; absent real financial schemas do not authorize installing them. Existing historical model journals/private 324-file inventory are **outside this backup scope**. Supabase Storage **object bytes**, Auth/API keys/settings, Edge Functions, Realtime, integrations, IAM/dashboard/network configuration, extension binaries and provider-managed configuration are not recreated by a PostgreSQL dump; inventory/export them separately only with approval. Database metadata may describe Storage objects but does not contain their bytes. [Vendor backup scope](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore), [role-password exclusion](https://www.postgresql.org/docs/17/app-pg-dumpall.html).
