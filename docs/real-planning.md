## Current flow

Homepage → existing local AI / deterministic clarification and overrides → backend-controlled real/mock mode → one Places search per distinct activity → canonical normalization, geographic checks, relevance and ID deduplication → geographic shortlist → necessary directed routes → existing candidate walker, evaluator, Task 44/45 evidence and ranking → diverse, source-labeled cards.

Initial discovery requests up to **10** results/category with explicit pageSize. Explicit Search for more venues actions fetch at most two result pages/refinements per action, retaining up to **20 relevant candidates/category** within **10 searches/outing**. A returned nextPageToken is requested explicitly in the field mask and kept only in the expiring active computation; it never enters result JSON, logs or disk. The next request preserves the original query, filters, meal context and area; only pageToken changes. When a query has no next page, the alternative query may run once, with its own returned pages. Bowling starts with `bowling alleys` plus strict `bowling_alley` filtering; the explicit `bowling centers` refinement removes that type restriction, but requires affirmative type/name evidence locally. The area never changes. At most six pages/category across both queries and ten searches across the outing; no automatic loop, token retry, geographic widening or irrelevant filler. Original IDs are retained and new results are normalized, filtered and deduplicated before filling free slots. See [Google's page controls and parameter requirements](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places/searchText). All 29 categories and ordered/repeated activities remain supported. The Pro mask adds types and primaryType to the existing identity/address/coordinate/components/attribution fields. Dinner-specific queries exclude affirmative cafe/coffee/bakery-only matches lacking restaurant-type evidence. Missing types do not reject a venue by themselves, and mixed cafe/restaurants remain provisional. The retained dinner warning prevents restaurant classification being represented as confirmed dinner service.

## Routing and recommendations

`routing_shortlist.py` computes forward/backward minimum straight-line path costs across the whole requested sequence. This is a geographic heuristic, never a driving/walking quote; strong relevance is preferred and stable IDs break ties. It is not an exclusively greedy next-stop search and does not claim global optimality. After shortlisting, the existing route calculator and candidate walker/evaluator enforce directed provider travel and all hard constraints. Missing legs stay unverified and unreachable legs reject combinations. Unknown prices cannot satisfy budgets. Dates, overrides, multi-activity identity and repeated-category rules remain.

| Two | 6 | 36 / 1 | 20 | 300 |
| Three | 4 | 32 / 2 | 12 | 300 |

*Disjoint groups; deduplication/self-identity can reduce counts, and overlapping groups can split rectangles differently. An authorized origin adds at most 6/4/4 initial elements. Expanded inventories are **not all routed at once**: stages reserve at most 64 new directed elements within the original **300-element, 30-attempt** outing ceilings and unchanged process/minute limits. Failed/reserved work is not refunded. An initial shortlist with fewer than three acceptable plans **or fewer than three eligible primary venues when more are retained** may make one further automatic bounded stage; subsequent exploration is explicit. Hard limits never loosen to fit a provider budget.

The existing score now uses a confidence-weighted rating quality component when evidence exists: `(rating × count + 3.5 × 50) / (count + 50)`, mapped onto 0–1 and averaged over all stops. Missing ratings contribute no invented rating; zero-count ratings are omitted. The 3.5/50 prior is a disclosed ranking heuristic, not provider data. Existing spending-mode weights remain; price remains absent. Ratings never override feasibility. Within the existing 0.15 score tolerance, diversity prefers unused primary venues, then meaningful full-itinerary changes, preserving better evidence/convenience outside that tolerance. Shared stops are allowed; duplicate ordered outings are not.
