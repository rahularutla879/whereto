## Recovery and rollback sequence

1. Stop new issuance before risky rollout/migration; observe active/uncertain work and leave conservative reservations intact. Approve schema/build compatibility and fresh image/secret identities.
2. Deploy a no-traffic revision; authenticated health/readiness uses no paid provider. Test caller denials, current epoch and private connectivity before a private canary.
3. On application regression, route private traffic back to an **approved-compatible** image/config. Never restore an older financial database, reset counters, re-enable old grants/keys or refund uncertainty as a software rollback.
4. On authority/database restore, stop/revoke dispatch, quarantine old epochs, reconcile independent intent/exposure evidence or the full at-risk grant, and require operator financial approval. If unresolved, keep unavailable. Backups/PITR do not make this automatic.
5. On Redis loss, expire affected outings and deny continuation. Never synthesize raw evidence from cards/saved snapshots or automatically buy fresh provider results to rebuild it.
