## Free availability and backup gate

The dashboard still shows Free,500MB database allowance/shared500MBRAM, no payment method/invoices and pausing after one inactive week. Supabase [documents pausing](https://supabase.com/docs/guides/deployment/going-into-prod) and recommends [off-site logical exports for Free](https://supabase.com/docs/guides/platform/backups). An occasional demo can tolerate an explicitly scheduled owner/admin unpause and non-billable readiness check; there is no always-ready guarantee and no paid keepalive should be invented.

Before any migration: separately authorize a protected logical export and current catalog/data baseline. Preserve required roles/memberships, ownership, grants, RLS, schema/functions/sequences and financial history; store encrypted archives outside Git and outside the database's restore control. Verify hashes and restore into a disposable matching-major database; compare baseline metadata/data and run existing protected restore/quarantine drills. Database dumps do not back up Supabase Storage objects or all dashboard/IAM configuration: inventory those independently. Export/backup egress counts toward allowances. The existing dump/restore tests use fictional databases; **no live owner backup has been created or verified**. Never restore both financial authorities together, renew an epoch/grant, or resend uncertain operations to recover a demo. A restore must reconcile with the independent witness and quarantine exposure when required. A manual backup plan needs a named operator, retention schedule and off-site destination; it cannot silently depend on the owner's Mac remaining online for application service.
