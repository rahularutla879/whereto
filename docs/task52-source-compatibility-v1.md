## Decision: immutable Git snapshots plus separately allowlisted manifests

| Approach | Benefits | Risks / decision |
|---|---|---|
| Copy frozen Python validators into the active package | Readable old bytes | Duplicate imports, stale dependencies and two semantic authorities; do not vendor a second runnable validator into runtime. |
| Exact Git commit/tree snapshot with dependency identity | Preserves full historical source including helpers/data without editing it | Git objects and matching dependencies must remain available. Retain the existing private remote/history and release artifacts; never rely on moving branch names. No fetching or restoration fallback during scoring. Recommended retention mechanism. |
| Immutable reviewed manifest | Explicit corpus/schema/policy/evaluator roles and content hashes | Hashes establish identity, not correctness or authorization; a self-supplied manifest is untrusted. Recommend an exact-byte allowlist in a separately reviewed tool. |
| Explicit runtime adapters | New validators can be compared against the frozen implementation | Only useful with named profiles, complete phase tests and no fallback/skip-validation switch. Future implementation, not enabled here. |
| Update old pins to current code | Easy to keep one working tree green | Erases the evidence boundary; rejected. A fresh journal/allowance is also rejected. |

Recommended combination: retain historical code in its exact Git snapshot, use an allowlisted identity manifest, introduce separately named future runtime adapters only after extraction approval. A source pin is an identity check, not an eternal prohibition on runtime changes. Changing runtime files legitimately requires a **new identity**, never falsely satisfying an old pin. The existing paid evaluator still checks its current checkout and must continue refusing changed sources. Do not edit that behavior.

For a future historical replay, use an isolated, network-disabled snapshot execution artifact with matching recorded dependencies, no credentials, and no writable paid journal. Preserve original input, schema and configuration, clock and evaluator identity. This checkpoint only reads Git objects; it does not create a checkout, execute old code, clone a journal or authorize paid dispatch. If a complete old dependency environment cannot be recovered, report reproduction unavailable rather than claiming byte identity guarantees equivalent behavior.

## Exact prototype format and trust boundary

[Manifest](task52-source-identities-v1.json), [offline checker](../scripts/task52_version_review.py), [tests](../backend/test_task52_version_review.py).

`52b-source-identities-v1` contains two **baseline-only** entries:

- `52b-historical-evaluator-b04`, role `historical_evaluator`: exact b04 implementation snapshot, **not** a replacement label for any original paid attempt.
- `52b-runtime-legacy-b04`, role `runtime_legacy_foundation`: same initial bytes, distinct purpose. This is not a V4 enforced version.

Each entry binds full `gitCommit`, `gitTree`, `corpusPath`, `corpusSHA256`, unchanged `originalSixPins`, `implementationRootSHA256`, `schemaIdentity`, dependency scope and purpose. The implementation root is SHA256 of canonical sorted path→SHA256 for all tracked backend files except `test_*` basenames plus `scripts/cloud_model52*.py`; this includes backend data as well as Python. Whole Git tree identity retains all other files. The checker has an exact manifest-byte SHA256 allowlist and fixed role set. Missing/unknown role, version, object, hash or altered manifest fails. No self-registration, runtime imports, dynamic Python execution, network, scoring, credential loading or journal access exists.

`verify(..., working=False)` proves retained snapshot identity only. `working=True` separately checks the currently selected source/data set and corpus; it does not assert entire checkout equality, installed dependency equivalence or semantic qualification. Synthetic changed-source tests demonstrate that snapshot verification can remain true while current-source equality fails. No old hash check was weakened. New runtime helpers cannot be hidden in the selected backend path set; deployment assets outside it require a new full runtime build manifest.

Future runtime manifests must add explicit adapter/phase versions, policy implementation/grammar hashes, canonical schema hash, decoder identity, dependency lock/build artifact hashes, input/output type versions, pending snapshot provenance format and admitted purpose set. Unknown combinations fail closed. No future V4 identity has been pre-approved here. The current manifest format must be revised rather than silently overloaded if new fields become authoritative.

For each paid attempt, the journal's original operation/case/repetition, configuration/prompt/schema/payload/response hashes, recorded classification and correction chain remain authoritative. Resolve its original implementation from its original evidence; do not assign all ten attempts the b04 evaluator label. The baseline catalog does not complete an automated per-attempt historical environment resolver.

A separate replay record must reference original operation and immutable evidence digest, original evaluator/configuration/model/prompt/schema identities, replay implementation/scorer/schema/clock identities, raw/effective provenance and review state. It must retain original outcome plus separately named replay outcome. The prototype `replay_descriptor` demonstrates immutable nesting and defaults to `unreviewed`; it is **not a scorer**, does not verify a caller's alleged original outcome, and cannot authorize an attempt. Its expected source digest must come from independently verified evidence. Real replay below uses the existing frozen offline runner and reports unchanged historical rows separately.

Rollback selects a retained runtime build/policy manifest only for cohorts already compatible with it. Revoke dependent new-work authorities on policy change. If an enforced profile is unsafe, close new-work admission; never fall back to legacy acceptance of its known invented edge. Saved viewing remains independent. No history, score or financial record is rewritten.
