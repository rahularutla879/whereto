## Count and inference

The factory validates the native original request, current HTTP/inference admission, encrypted source commitment, source hash, revision/fence and exact full Responses bytes. A separate fresh-inference registration permits active admission without weakening the original completed-source registration. SQL pins the complete template and input-bearing count projection; each capability permits one count attempt only.

The counter has only restricted count routines and a **count-only witness principal**. It has no issuer, grant operator, generation or epoch-rotation authority, and does not receive private Redis keys. The factory checks Redis before count enrollment; SQL rechecks the protected commitment/admission. Paid generation independently rechecks encrypted evidence. Count freshness is rechecked at approval, reservation, dispatch and the final accounting receipt; approval cannot preserve an expired count. Count attempt, reservation, INTENT/dispatch and delivery permission are durably mirrored through the same witness history **before** the existing callback loads credentials or performs I/O. Malformed, absent, excessive or interrupted counts never enable generation/retry. Ambiguity quarantines; a replacement process cannot reuse the consumed attempt.

Only explicitly reviewed **zero-fee** counting is supported in this version. Unknown/nonzero count fees refuse instead of borrowing inference allowance. Actual count results bind raw-response digest, exact generation/count digests, project, approved revision and current source. Expiry is no later than session expiry and the approved count TTL (1–600 seconds). SQL adds the operator-approved conservative margin, enforces input ceiling and maximum output (up to 2,000), then derives the LLM specification itself. No UTF-8 byte count or historical 5,704-token count is used.

Reservation uses micro-USD integer arithmetic: `ceil(bounded_input × input_microUSD_per_million / 1,000,000) + ceil(bounded_input × cache_write_microUSD_per_million / 1,000,000) + ceil(max_output × output_microUSD_per_million / 1,000,000)`. Full input is charged without an assumed cached-input discount; worst-case full cache-write cost is also reserved. Maximum output includes invisible tokens. Tools, extra fees, premium service tiers and unknown categories are refused. Qualification/account evidence must establish that these are all applicable categories; an unenforceable alias/revision or unbounded cost refuses enrollment.

Reported input/output/cache-read/cache-write/reasoning/tool usage is informational. Invalid or contradictory reports quarantine; valid reports, zero output and provider failure **never refund or release** the conservative reservation. The diagnostic experiment's nanodollars/journal remain entirely separate.
