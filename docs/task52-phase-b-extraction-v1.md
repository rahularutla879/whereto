## Record and mapping contract

`PreparedSource`, `Occurrence` and `OccurrenceMapping` are frozen, non-data-bearing representations with immutable bytes/tuples. They are transient private request objects, never operational logs, persistence, response fields, capabilities or validation certificates. Python code can construct/copy them; that grants no authority. Trusted constructors expect the existing strict input/extraction path. The complete deep-copied input also remains in `LegacyDisposition.input`.

- `basis_snapshot` is typed canonical extraction, **not original provider wire bytes**. Separate `explicit_fields` preserves available parsed field-presence paths. The decoder remains responsible for duplicates and unknown JSON properties.
- `source_kind=raw_model` is only used after fresh provider extraction. `legacy_effective_pending` remains an effective legacy snapshot. A matching pending input cannot be captured through the fresh-origin helper branch. Saved itineraries are never treated as model evidence.
- Local logical IDs `basis:0`, `basis:1`, etc. identify original **activity-array occurrences inside this record**. They are not global/cross-request IDs, bearer secrets or confirmed venue identities. `journey_index` is assigned only when the whole original journey stop list exactly aligns with activities; otherwise it stays unresolved. The original journey and every raw stop remain in canonical bytes regardless of alignment.
- A `span` proves a bounded lexical association only. `evidence_span`/`lexically_bound` means a unique literal quote occurrence contains that lexical activity span; it does **not** prove qualifier scope, requiredness, venue identity, relation direction, edge ownership or full semantic correctness. Long evidence containing several stops must still pass independent source/ordering validation. Empty evidence remains `unspecified`; hallucinated/mismatched evidence remains `unresolved` and does not waive any validator.
- Original/effective index mappings are observational: `same_source_span` is not an authorization or claim that kind/optionality/durations stayed unchanged. Those differences remain inspectable in the two snapshots. Every unmatched/ambiguous occurrence maps to `None`; no ordinal alignment or silent endpoint conversion is invented.
- `coffee twice` keeps two original logical visits with unresolved separate lexical spans. The existing validator's count convention still decides the live result. Two explicit coffee mentions can have distinct unique spans. A removed `go home` occurrence remains in the basis and maps unresolved, rather than acquiring an invented endpoint index.
- Matching pending uses its existing `referenceTime`; explicit `now` is preserved. Without either, the record says `legacy_clock_unobserved` and leaves its reference null; it does not pretend an independently read clock is the actual legacy resolver clock. Current and saved answer snapshots stay separate.

No preparation output is consumed by routing, sessions, ordering shadow, source-grounding decisions or admission issuance. Even advanced handoff authority is issued only by the original full legacy classification and cannot authorize provider work.
