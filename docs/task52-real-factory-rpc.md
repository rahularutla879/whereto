## Functional connections

`real_application/factory.py` reuses the existing opaque encrypted locator and SQL CAS/ownership routing algorithms, with an independently versioned real source cohort. The existing workload/IAP/request-body proof verifier supplies the owner; browser identity headers, native graphs, financial roots and provider receipts are not authority. Initial interpretation runs the native broker once, then checkpoints only the permitted original request/interpretation/answers/device-origin state. The public optional `52-private-ordinary-outing-v1` extension remains unchanged. Resumption checks original source, owner, build, revision, absolute expiry, completed inference, original root/outing, SQL fence, independent epoch and encrypted evidence. Deterministic date answers neither recount nor reinfer. Planning uses the original planner, consumes/revokes its source turn, and returns terminal cards without another handle. Meaning-changing inputs refuse; only validated device-coordinate execution control is admitted. No Google graph, route response, callback or itinerary snapshot is persisted.

`rpc.py` binds the existing authenticated `/count` and `/send` methods to actual real-profile SQL/witness authority. The counter receives the complete exact generation request and protected capability identity, uses its count-only SQL/witness login and cannot generate. Its returned JSON is not a permit: the factory independently reads protected SQL count evidence before reservation. The dispatcher uses a delivery-only SQL front door and protected accounting receipt; request JSON cannot set prices, budgets or receipts. Factory-owned permits retain exact operation, ordinal, canonical payload digest, process boot, workload identity, build and epoch. The existing router chooses only configured owner slots, never a caller URL. A replacement factory may resume a valid source with a new fence; it cannot take an old process's callback permit. An uncertain send retains exposure and never automatically resends.

`rpc_sql.py` projects only the original fixed service-route, restricted delivery, witness-phase and nonce routines into the existing real namespace/roles. It inserts no rate, financial grant, credential or epoch and changes no original financial algorithm. `service.py` supplies the existing authenticated HTTP/FastAPI handlers with explicit real dependencies. Each local process receives only its own signing key and necessary SQL/Redis credentials. The source manifest verifies reused source bytes **before** compilation/projection. The old v2 manifest is preserved byte-for-byte as `sources-native-v2.json`; the new v3 manifest remains `releaseEligible=false`.

Two small native fixes accompany the mapping: validated device controls reissue existing native admission when an initially complete interpretation had no origin; terminal continuation status is a typed DTO instead of an unchecked dictionary, with unchanged JSON. Neither changes planner, source semantics, pricing or saved-plan contracts.
